01 The Spatial Problem

Why Plain-Text OCR Fails on Modern Documents

Standard OCR squashes 2D document pages into a 1D text stream. Without spatial coordinate grounding, multi-column tables collapse and nested modifiers are severed from their parent rows.

Traditional Plain-Text OCR 1D Stream Collapse

Scans sequentially across columns. Destroys horizontal row alignment, mixes headers into data cells, and loses discount or modifier parent-child relationships.

Cloud Cluster Compute $900.00 Qty 2 ↳ Priority 24/7 SLA +$350.00 Layout Engine Site License $700.00 ↳ Startup Volume Discount -$100.00 Subtotal $3,250.00 Tax $200.00 Total $3,450.00 [Stream parser loses modifier indentation and merges prices into base rows]
StackDoc 2D Layout AI 2D Coordinate Grounding

Maintains spatial coordinates [x0, y0, x1, y1]. Binds table columns by horizontal X-intervals, groups parent-child modifiers by indentation (Δx0 > 12px), and verifies arithmetic.

02 Architecture

3-Stage Document Understanding Architecture

A hybrid design that reads digital vector text directly and routes scans to neural OCR, followed by deterministic spatial grouping and arithmetic validation.

1 Modality & Vector Router

Inspects incoming document format. Digital PDFs with embedded font streams route directly to coordinate extraction (pdf.js). Raster scans and photos route to the OCR pipeline.

Instant routing
2 Dual Coordinate Extractor

Digital PDFs: exact vector text and bounding boxes [x0, y0, x1, y1] read directly without OCR errors. Scanned images: Tesseract.js neural OCR extracts words and spatial geometry in-browser.

<0.03s Digital / ~2–5s OCR
3 Structured Post-Processor & Audit

Clusters table lines by vertical Y-intervals, links indented modifiers (Δx0 > 12px) to parent rows, and executes deterministic arithmetic verification (Subtotal + Tax == Total).

Deterministic math check

04 Comparative Analysis

Architectural Trade-offs

Why our system implements a hybrid dual-engine architecture instead of relying on a single monolithic model.

Dimension StackDoc Hybrid (Ours) Donut (Vision-Language) LayoutLMv3 (Multimodal)
Input Modality Dual-mode: Vector coordinates for PDFs, direct pixels for scans. Raw image pixels directly via Swin Transformer encoder. Requires external OCR pre-step to generate word boxes.
OCR Dependency Direct text reads for digital PDFs; In-browser OCR for scans. Self-contained weights; no external OCR binary. Strict dependency on external OCR (Tesseract / cloud OCR).
Nested Modifiers Deterministic spatial indentation clustering (Δx0 > 12px). Sequence autoregression (can hallucinate order). Bounding box coordinate embedding.
Latency Profile <0.03s for vector PDFs (direct text); ~2–5s for photo OCR (Tesseract.js). 2.7s – 4.5s (typical published range, not measured by us). 0.35s – 1.2s plus OCR (typical published range, not measured by us).
Arithmetic Audit Deterministic math reconciliation (Subtotal + Tax == Total). None (black-box neural token generation). None (requires downstream logic).
05 Browser Extension

Chrome Extension (Manifest V3) & Local Backend

The Chrome Extension lets you capture active invoice tabs or drop files to inspect structured bounding box overlays via a local FastAPI backend.

Download Extension (.zip)
Step 1 Download & Unpack Download stackdoc-extension.zip and unpack it, or use the extension/ directory in the repo.
Step 2 Open Extensions Navigate to chrome://extensions in Chrome, Brave, or Edge.
Step 3 Developer Mode Enable the "Developer mode" toggle switch in the top-right corner.
Step 4 Load Unpacked Click "Load unpacked" and select the unzipped folder containing manifest.json.

Running the Local Backend Server (Optional)

The static GitHub Pages site runs in-browser without a backend. To run the full Python FastAPI server for batch processing: 

# Install dependencies and start FastAPI server
python -m venv venv && source venv/bin/activate
pip install -r backend/requirements.txt
uvicorn backend.main:app --reload --port 8000
