01 The Fundamental Problem

Why Plain-Text OCR Fails on Modern Documents

Standard OCR squashes rich 2D document pages into an ambiguous 1D text stream. Without spatial geometry and coordinates, multi-column tables collapse and nested modifiers are lost.

❌ Traditional Plain-Text OCR Brittle Stream

Scans left-to-right, top-to-bottom across columns. Destroys horizontal row alignment, mashes headers into data cells, and loses discount/modifier relationships.

Cloud Cluster Compute $900.00 Qty 2 ↳ Priority 24/7 SLA +$350.00 Layout Engine Site License $700.00 ↳ Startup Volume Discount -$100.00 Subtotal $3,250.00 Tax $200.00 Total $3,450.00 [Error: Stream parser merges modifier prices into base line totals]
✓ StackDoc 2D Layout AI Layout-Aware Grounding

Maintains spatial coordinates [x0, y0, x1, y1]. Binds table columns by X-ranges, reconstructs parent-child modifier trees by indentation (Δx0 > 12px), and verifies math.

02 Architecture & Engineering

Our 3-Stage Document Understanding Pipeline

Designed for maximum speed, zero brittle OCR binaries, and deterministic mathematical accuracy.

1 Format & Modality Router

Analyzes incoming document structure. If digital vector text density > 20 words, routes to the lightning-fast 2D spatial layout parser (<0.03s). Flat images and scans route to Vision AI.

<0.001s Latency
2 Dual-Engine Layout Parser

Extracts coordinate-grounded word tokens [x0, y0, x1, y1]. Digital PDFs use direct coordinate geometry; scans run through vision autoregression without OCR bottlenecks.

<0.03s Digital / 3.2s Vision
3 Structured Post-Processor

Reconstructs hierarchical nested modifier trees via indentation clustering (Δx0 > 12px), normalizes ISO-8601 dates, and executes deterministic arithmetic verification (Subtotal + Tax == Total).

<0.002s Execution

04 Architectural Trade-offs

Donut vs. LayoutLMv3 vs. StackDoc

Why our system implements a hybrid dual-engine architecture instead of relying on a monolithic OCR-dependent model.

Dimension StackDoc Hybrid (Ours) Donut (Vision-Language) LayoutLMv3 (Multimodal)
Input Modality Dual-mode: Vector coordinates for PDFs, direct pixels for scans. Raw image pixels directly via Swin Transformer encoder. Requires external OCR pre-step to generate word boxes.
OCR Dependency Zero OCR for digital PDFs; In-browser vision for scans. Zero external OCR binaries. Self-contained weights. Strict dependency on Tesseract / system OCR binaries.
Nested Modifiers Deterministic spatial indentation clustering (Δx0 > 12px). Sequence autoregression (can hallucinate order). Bounding box coordinate embedding.
Latency Profile <0.03s for 95% of corporate invoices (Digital PDFs). 2.7s – 4.5s autoregressive token generation. 0.35s – 1.2s plus external OCR time.
Arithmetic Audit Deterministic Stage 3 math reconciliation engine. None (black-box neural generation). None (requires downstream logic).
05 Deployment & Extension

1-Click Chrome Extension & Local FastAPI

Extract structured data while browsing invoices or connect your local backend server.

Step 1 Open Extensions Navigate to chrome://extensions in Chrome or Brave.
Step 2 Developer Mode Enable the "Developer mode" toggle switch in the top-right corner.
Step 3 Load Unpacked Click "Load unpacked" and select the extension/ directory.
Step 4 Pin Extension Pin the StackDoc icon to your browser bar for 1-click document parsing.

Running the Local Backend Server (Optional)

The static web app works 100% autonomously in the browser. You can also run the full Python FastAPI server for high-throughput batch processing: 

# Install dependencies and start FastAPI server
python -m venv venv && source venv/bin/activate
pip install -r backend/requirements.txt
uvicorn backend.main:app --reload --port 8000
