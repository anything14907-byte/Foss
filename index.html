Architectural Analysis: Donut vs LayoutLMv3

An honest technical breakdown of trade-offs between Vision-Language Transformers and OCR-reliant multi-modal architectures.

Donut (Document Understanding Transformer)

Architecture End-to-end Vision-Language Model (Swin Transformer + mBART). Takes raw image pixels directly.
OCR Pipeline Zero OCR dependency. No external binaries (Tesseract/EasyOCR) or bounding-box generators needed.
Strengths Immune to OCR word-splitting bugs; fast single-pass inference on receipts; compact deployment footprint.
Limitations & Hallucination Risk Autoregressive decoder can hallucinate repeated or fabricated tokens on out-of-distribution layouts; pretrained CORD checkpoint is tailored for receipts rather than full-page complex tax forms.

LayoutLMv3 (Multi-Modal Transformer)

Architecture Multi-modal text + 2D coordinate embeddings + visual patch tokens.
OCR Pipeline Strict dependency on external OCR pipeline to compute word-level coordinates (x0, y0, x1, y1) prior to forward pass.
Strengths Grounds extraction directly in OCR word boxes; strong token classification accuracy on complex dense forms.
Limitations & Vulnerability Pipeline fails catastrophically if OCR produces errors or misses words; heavy environment setup; coordinate preprocessing overhead.

Known Limitations & Engineering Roadmap

Engineering transparency regarding current scope and upcoming releases.

Receipt-Trained Weights

The CORD checkpoint specializes in receipt semantics. Digital invoices with complex corporate headers require fine-tuning or the coordinate layout path.

Multi-Page Tables

Digital PDF tables continuing across pages are supported via coordinate alignment; extending autoregressive VLM attention across multi-page scans is in progress.

Nested Item Structures

Modifiers (e.g. customized toppings or nested SKU discounts) are currently flattened into primary item lines.

Handwriting Recognition

Faded handwriting and handwritten totals are outside the scope of current digital & receipt models.

Run It Locally

Complete reproducible instructions to run the FastAPI backend, evaluation suite, and Chrome extension. 

# 1. Clone repository and set up virtual environment
git clone https://github.com/anything14907-byte/Foss.git
cd Foss
python3 -m venv venv
source venv/bin/activate

# 2. Install pinned dependencies (including dev pytest)
pip install -r requirements.txt

# 3. Pre-cache model weights for 100% offline hackathon execution
python scripts/download_model.py

# 4. Start local FastAPI backend (runs on http://localhost:8000)
bash scripts/start_server.sh

# 5. Run evaluation benchmark & pytest
python evaluate.py
pytest tests/
